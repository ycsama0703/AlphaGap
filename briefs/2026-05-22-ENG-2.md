# RecursiveMAS的递归多智能体协作可诊断多因子组合中的冲突与冗余

## 1. The Core Insight
多因子组合的核心矛盾在于：因子间信号存在大量重叠与冲突，但传统加权方法（等权、优化）是静态的，无法在推理时动态识别并消解这些冗余。RecursiveMAS 的递归潜空间协作机制恰好提供了一种“让因子们互相讨论、迭代收敛到共识”的计算范式——这本质上是将组合优化问题从“一次性加权”转化为“多轮协商”，利用递归计算来逼近因子间复杂依赖关系的稳态解。

## 2. Conceptual Mapping (AI ↔ Fin)
- **AI 侧**：RecursiveMAS 处理的是 heterogeneous agents（如不同功能的 LLM agent），每个 agent 有自己的输入/输出空间，通过 RecursiveLink 模块在统一潜空间进行递归信息交换，迭代更新各自的 hidden state，最终输出协作后的结果。核心结构是：agent 数量固定、通信协议统一、递归轮次可调。
- **Fin 侧**：多因子组合中，每个因子（如动量、价值）可以自然地映射为一个 agent。每个 agent 的“输入”是历史因子收益序列和当前权重，“输出”是因子信号和置信度。这构成了一个同构的 multi-agent system。
- **Bridge 搭法**：直接对应，无需改造架构。关键工程细节是：
  1. 定义每个因子 agent 的“潜空间表示”——可以是因子收益序列的 embedding（如 LSTM 输出），也可以是因子当前暴露度的向量。
  2. 设计 RecursiveLink 的通信内容——是交换原始信号、置信度，还是交换梯度/注意力权重？这需要实验确定。
  3. 递归轮次 T 需要与金融时序的“信息衰减速度”对齐——因子间的冗余信息可能在 2-3 轮后收敛，过多轮次可能导致过拟合。
- **不直接对应的情境**：如果因子数量极少（<3），递归协作的收益可能被通信开销抵消；如果因子间完全正交（无冗余），递归协作无意义。

## 3. Data Requirements (shape, not acquisition)
- **维度**：Panel data（股票 × 时间 × 因子）。每个时间点 t，有 N 只股票，每只股票有 K 个因子暴露度（如动量、价值等）和未来收益（标签）。
- **必需的特征类型**：因子暴露度（标准化后）+ 未来收益（如 t+1 日收益）。不需要 firm characteristics，但因子暴露度本身可以是 firm characteristics 的函数。
- **时序长度 / 样本量需求**：最少需要 500 个交易日（约 2 年）才能让递归协作的收敛模式稳定。因子数量 K 建议 ≥ 5，否则递归优势不明显。股票数量 N 建议 ≥ 500（如 S&P 500 成分股）。
- **标签来源选项**：
  - **Option A（推荐）**：未来 1 日收益（回归任务）。优点：信号直接、可回测。缺点：噪声大。
  - **Option B**：未来 20 日收益（回归或排序）。优点：信号更稳定。缺点：样本重叠、统计检验复杂。
  - **Option C**：未来 1 日收益的 rank（排序任务）。优点：减少极端值影响。缺点：丢失幅度信息。

## 4. Benchmark Landscape
这个 Fin 子领域（多因子组合）目前有三个主要流派：

1. **静态加权流派**：核心假设是因子间关系是稳定的，可以用历史协方差矩阵一次性求解最优权重。代表工作：Markowitz (1952) 均值-方差优化、等权组合（DeMiguel et al. 2009）。**本 gap 的差异化**：引入动态递归协作，打破静态假设。

2. **时序动态加权流派**：核心假设是因子权重应随时间变化，通常用滚动窗口或 regime-switching 模型。代表工作：Barberis (2000) 基于状态切换的因子择时、Rapach et al. (2010) 组合预测。**本 gap 的差异化**：从“因子择时”转向“因子间关系诊断”，通过递归协作显式建模因子间冗余。

3. **图网络因子组合流派**：核心假设是因子间关系可以用图结构表示，通过 GCN/GAT 学习因子间依赖。代表工作：Feng et al. (2019) 基于 GCN 的因子组合、Chen et al. (2021) 动态图因子模型。**本 gap 的差异化**：图网络是单次前向传播，而 RecursiveMAS 是递归迭代——后者能捕捉因子间关系的“多轮协商”动态，理论上能处理更复杂的非线性依赖。

**本 gap 的定位**：属于第 3 流派的延伸，但引入了递归计算范式，可能开创“递归因子协作”子方向。

## 5. Where to Start (Reading + Replication Order)
- **第 1 步：读 RecursiveMAS 论文 [2604.25917]**。重点理解 RecursiveLink 模块的具体实现、递归轮次 T 的选择策略、以及 heterogeneous agents 的通信协议设计。同时读 Feng et al. (2019) 的 GCN 因子组合论文，理解图网络如何建模因子关系。
- **第 2 步：复现 Feng et al. (2019) 的 GCN 因子组合 baseline**。使用给定数据（美股日频 10 因子，2000-2023），确认环境 work，并记录等权、均值-方差、GCN 三个 baseline 的 Sharpe 和因子冗余度。
- **第 3 步：做第一个真实验——单股票递归协作**。选一只流动性好的股票（如 AAPL），用其 10 个因子暴露度序列，构建一个简化版 RecursiveMAS：每个因子 agent 是一个单层 MLP，递归轮次 T=3，输出因子权重。对比单次通信（T=1）和递归协作（T=3）的 Sharpe 差异。
  - **如果第 3 步过了**（递归协作 Sharpe 显著高于单次通信）：扩展到全市场股票，加入 RecursiveLink 的完整实现，做完整回测。
  - **如果第 3 步没过**（递归协作无显著提升）：pivot 到两个方向：(a) 增加因子 agent 的复杂度（如用 LSTM 替代 MLP），(b) 改变通信协议（从交换信号改为交换注意力权重）。

## 6. The True Contribution
- **(a) Empirical contribution**：第一次实证证明，递归多智能体协作可以在多因子组合中动态识别并消解因子间冗余，提升组合 Sharpe 并降低因子间平均相关性。
- **(b) Methodological contribution**：提供了“因子 agent 化 + 递归潜空间通信”的通用框架，将 RecursiveMAS 从 LLM agent 领域迁移到金融因子组合领域，并验证了其有效性。
- **(c) Theoretical contribution**：在“因子间关系建模”的 framework 下，引入了“递归收敛”的概念——因子间冗余不是静态的，而是可以通过多轮协商动态逼近稳态解。这为因子组合理论提供了一个新的计算视角。

## 7. Conceptual Risks
- **致命风险**：递归协作可能只是“过拟合噪声”。因子间冗余在金融数据中可能并不需要多轮协商——单次图网络可能已经足够。**Mitigation**：在合成数据上先验证——生成已知冗余结构的因子数据（如 5 个因子中 2 个完全相关），看递归协作是否能比 GCN 更快/更准地识别冗余。如果合成数据上都不 work，则整个 idea 崩塌。
- **重要风险**：递归轮次 T 的选取可能高度敏感。金融时序非平稳，最优 T 可能随时间变化，导致需要在线调参。**降级路径**：如果 T 敏感，可以改为自适应 T（如当 agent 间信号变化小于阈值时停止递归），但这会引入额外超参数。
- **可接受风险**：因子数量较少（如 5 个）时递归优势不明显。这可以通过在更多因子上测试（如 20 个因子）来缓解。如果仍然不显著，则贡献降级为“递归协作在因子数量较多时有效”。
